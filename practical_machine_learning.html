Executive summary

This analysis predicts how participants performed a barbell lift from accelerometers placed on the belt, forearm, arm, and dumbbell. The target, classe, has five levels. Class A represents the correct movement; classes B through E represent four common mistakes.

The source contains 19,622 labeled observations and 20 quiz cases. After identifiers, names, timestamps, window fields, sparse measurements, and a CSV row-number field were removed, 52 complete sensor predictors remained. A random forest was selected because the measurements interact nonlinearly and several orientation, acceleration, gyroscope, and magnetometer signals are correlated.

The random forest achieved 99.61% accuracy on a 4,906-row validation set that was not used for training or tuning. The corresponding estimated out-of-sample error is 0.39%. A separate five-fold ensemble check averaged 99.68% accuracy (standard deviation 0.10 percentage points). The final model was fitted to all labeled rows and used to predict the 20 quiz cases.

Data preparation

The training data contain 160 columns. Many summary fields are populated only for a small subset of rows. I used a transparent preprocessing rule: retain numeric sensor variables that are complete in both the training and quiz data. I then excluded the following metadata before any split or resampling:

  • CSV row identifier
  • participant name
  • raw and formatted timestamps
  • window indicators and window number
  • outcome and quiz identifier

These fields describe the collection session rather than the physical movement. Including the row identifier, in particular, produces unrealistically perfect validation results and unstable quiz predictions. Removing it is therefore a leakage control, not merely a convenience.

All five classes have thousands of examples, so no class weighting or synthetic balancing was necessary. A stratified split assigned 75% of the data (14,716 rows) to model building and 25% (4,906 rows) to final validation while preserving these proportions.

The reproducible R Markdown source implements the preparation rule directly:

Model building and cross-validation

A single decision tree served as a baseline. It is easy to interpret but sensitive to small changes in the data. Random forests reduce this variance by averaging many trees, with a random subset of predictors considered at each split. That structure suits the nonlinear boundaries in multi-device motion signals without requiring feature scaling.

Within the 75% build sample, five stratified folds were used to choose mtry, the number of predictors considered at each tree split. Candidate values were 4, 7, and 10. Each candidate was scored on rows omitted from the corresponding fold. The validation set was not used in this choice.

Candidate Validation accuracy
Decision tree 95.72%
Random forest 99.61%
Extra-trees robustness check 99.49%

The ensembles clearly outperform the single tree. The random forest was retained because it had the highest accuracy on the untouched validation sample. The extra-trees model was used as an independent robustness check across five folds; its fold accuracies ranged from 99.57% to 99.82%, with a mean of 99.68%.

The core R training call is:

control <- trainControl(method = "cv", number = 5,
                        savePredictions = "final")
rf_fit <- train(classe ~ ., data = build, method = "rf",
                trControl = control, metric = "Accuracy",
                tuneGrid = data.frame(mtry = c(4, 7, 10)),
                ntree = 500, importance = TRUE)

Out-of-sample performance

The selected model correctly classified 4,887 of 4,906 held-out rows. Accuracy was 99.61%, so the estimated out-of-sample error is 0.39% for observations drawn in the same way as this data set.

Observed  Predicted A B C D E
A 1,395 0 0 0 0
B 5 944 0 0 0
C 0 1 855 0 0
D 0 0 12 791 1
E 0 0 0 0 902

The model classified every held-out A and E observation correctly. Most of the 19 errors involved D movements classified as C. Errors are small relative to every class total, so there is no evidence that the overall score hides a poorly served class.

This estimate has an important limitation. The random split can place records from the same participant in both the build and validation sets. The reported error therefore measures performance on new records from the course data-generating process, not necessarily on entirely new people, sensor placements, or devices. Participant-grouped validation would answer that harder deployment question but would not match the standard course evaluation setup.

Important measurements

Belt roll and yaw, forearm pitch and roll, and dumbbell magnetometer measurements are among the strongest predictors. This is physically plausible because incorrect lifts change both limb orientation and the path of the weight. The importance scores are descriptive rather than causal. Correlated sensors can divide importance between themselves, and impurity-based measures can favor variables with more possible split points.

Reproducibility

The project includes the R Markdown source, a fixed random seed, explicit missing-value codes, a recorded feature-selection rule, stratified cross-validation, and relative paths. If the source CSV files are absent, the R Markdown downloads them from the public course URLs. Open the project folder in RStudio and knit practical_machine_learning.Rmd. The required packages are caret, randomForest, and rmarkdown.

Data sources: Practical Machine Learning training data, quiz data, and the Weight Lifting Exercise Dataset.
